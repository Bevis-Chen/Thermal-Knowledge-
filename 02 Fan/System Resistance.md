## 前言
當架設好系統需要選用風扇，會因而了解風扇PQ曲線、知道風扇不是只有字面上風流量大跟轉速高就好。當風扇建立壓差推動空氣進入系統內部，很明顯的風道比較寬以及散熱鰭片比較疏的地方能讓空氣比較順利流走、反之空氣則是比較容易出現擾流或帶不走。流體流經系統的時候，由於流體的機械能被摩擦以及局部流動損失所消耗，因此系統兩端會產生壓力差。我們知道系統(這裡專指伺服器)的阻抗可以將系統架設在風洞上得到阻抗曲線。那如何理解阻抗曲線的意義則需要一步步拆解。

## 壓力損失 Pressure Loss
風扇建立壓差讓空氣流動進入系統帶走熱或者流進風道，但是我們發現系統不能夠因此擁有無限制地增加流量。想像一個水管、從一邊流入空氣，當空氣流經管子再流到另一邊，空氣會因為管壁摩擦力的損耗、也許遇到管壁的管徑變化、甚至彎管以及其他零組件，最後最開始的空氣的總壓流到最後總壓不同(可以說下降了)。

如果是空氣進入系統(伺服器)後，風進入系統後，可能會遇到GPU、遇到CPU等等，還有大大小小的系統內部元件。為了讓系統得到一定的風量、還要克服這些壓力損失，風扇必須提高建立壓差能力(轉速或是更加優化風扇性能)。我們也可以透過能量守恆定律，了解到如果空氣從管道或者是系統的一邊流動至另一邊，不可能無緣無故的從流入的一邊總壓到另一邊就損耗減少。

## 達西–魏斯巴赫方程 Darcy–Weisbach equation

那如何描述壓力損失的數值，或者說如何得知壓力損失了多少? Darcy–Weisbach equation描述水頭損失：  
**h = f * (L/D) * (V²/2g)**
達西-魏斯巴赫公式想表達在一個流體流動的流道中，其沿程摩擦所造成的水頭損失 : 
  * 流道長度 L（單位 m公尺)
  * 流道直徑 D (單位 m公尺)
  * 流體平均速度之2次方 V² (單位 m/s)
  * 重力加速度 g (9.81 m/s²)
  * 摩擦因子 f :也稱為 **沿程阻力系數** ，是無量綱之物理量。摩擦因子 f 與流體黏度、雷諾數Re以及流道管壁相對粗糙程度 ε/D 有關，所以不是固定數值。

以上要素所組成。以上結果得出h單位為 m(米)。若轉換為壓力損失 ΔP 則需要乘上 ρg (流體密度 x 重力加速度)。不過還要特別說明，達西–魏斯巴赫方程對於其他損失，Darcy–Weisbach equation描述著通用工程方程由於流體沿著一個管路裡面因為不同粗糙表面而有了摩擦損失，但仍需要先確認不同的流動條件與模型來能否使用。比如管路彎頭、系統管道內部元件造程損失則是由其他局部壓力損失係數表達。

管路的損耗其實分成主要損失（Major Losses）以及 次要損失（Minor Losses），兩者構成總壓力損失。但實際伺服器內部還會有其他零件造成壓力損失。主要損失Major Loss的案例是由於管路管道裡面的壁面摩擦; 次要損失Minor Losses則是因為管路裡面的縮口/擴口/彎頭...等，屬於局部流動損失。可是這世界上不是所有東西是管道跟管路，比如伺服器或者個人電腦裡面充滿各種元件，而這些還會造成流動阻力。所以本篇章到這裡可以說，在現實世界裡無法僅透過Darcy–Weisbach方程來解釋壓力損失，要討論非管道管路的元件造成的壓降、需要元件的規格書以及實驗測量或者流體模型等的資訊進一步評估。之後的文章會再討論Minor Loss / Component Pressure Drop的詳細內容。

## 壓力與流量的關係
  **流量**
    ` Q = A * V `透過流量計可以知道當下流量Q，A是流體流過的截面積，V是流體平均速度。

我們知道達西-魏斯巴赫公式 h = f * (L/D) * (V²/2g) 代表著水頭損失，所以再乘上ρg之後: ΔP  = ρgh， 也就是壓力損失 ΔP = f * (ρgL/D) * (V²/2g) = f(ρLV²/2D) (g重力加速度被消除了。) 。我們再加入流量的公式 Q = A * V ，V²可以替代為(Q/A)²、也可以是Q²/A²。可以整合為 ΔP = (ρfL/2DA²)x(Q²)
若 簡化 ρfL/2DA² 為 K，也就是 K = ρfL/2DA² >> `ΔPpipe ≈ Kpipe * Q²`

管路壓力損失的推導到這裡，我們知道壓力損失增加與流量增加之2次方近似成正比，當流量增加，同時其他條件不變則壓力損失也會增加。進一步說、在流道幾何、流體性質以及其他條件固定，且流動狀態與摩擦因子可視為近似固定的情況下，壓力損失可近似與流量的平方成正比，因此實際系統曲線常以 `ΔPsystem ≈ Ksystem * Q²` 近似描述。

## 阻抗曲線

真正系統流量不完全是透過達西-魏斯巴赫公式就可以描述，我們推導到這裡只是初步了解一個管路裡面是固定條件下的結論。我們綜合知道: 當流體流進一個管道或是管路甚至伺服器裡面，會因為內部管壁的摩擦、以及伺服器的散熱鰭片等等造成壓力損失。如果在花園澆水發現水管的水太小、需要加大水龍頭的水; 又如同我們在伺服器內部發現風量不夠，會想要提高風扇轉速。 但是需要多少流量來克服壓力損失? 上述的公式推導告訴我們 **ΔP 正比於 Q²** : 流量的2次方。

> 當流體通過系統、因為系統內部有零件對於流體產生阻力而有壓力損失
> 合理推斷為了維持相同流量、所以需要產生流體的靜壓增加; (上述推論的`ΔPsystem≈KsystemQ²`)，在伺服器應用上，當風扇提供更高流量、流速上升、由於內部零件導致帶著機械能的流量損失了、系統壓力損失也跟著上升，最後導致需要風扇提供更高壓差
> 不同系統壓差與流量最後畫出曲線 System Impedance Curve

當然實務上除了公式推導，模擬CFD運算出 System Impedance Curve，其實實務上伺服器都會透過風洞量測、改變系統流量找出對應壓差，取得實際的 System Impedance Curve。

#### 最後的最後

在系統裡面風扇提供了需要的壓差，系統因為內部零件有了流動阻力所以會有壓力損失。當我們把FAN PQ 與 System Impedance 曲線放在一起相交，兩者同時滿足就會是系統實際運作的 Working Point。下一章節: 工作點，以及匯集 FAN PQ，系統阻抗的總章。
