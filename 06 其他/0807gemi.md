# 伺服器熱負載測試：軟體對硬體底層的物理壓榨原理  

在伺服器硬體測試中，軟體既不生產電壓，也不製造電流。軟體對硬體的壓榨，本質上是透過
**「指令流」控制晶片內部的電晶體、電容與物理通道，使其在極短時間內達到最大頻率的電訊號翻轉（Toggle）**，進而將功耗、熱量、I/O 吞吐量推向物理極限。

---
# 一、 CPU & GPU：為什麼軟體能讓瓦數（功耗）衝到最高？  

晶片消耗瓦數的物理本質是：**動態功耗 = 1/2 × 電容 × 電壓² × 翻轉率（Toggle Rate）。**  
當電晶體維持 `0` 或 `1` 不動時，只有微小的漏電流（靜態功耗）；但當它在 `0` 與 `1` 之間瘋狂切換時，電容頻繁充放電，電流就會暴增。測試軟體（如 Prime95, Linpack, FurMark）是透過以下三種架構手段把翻轉率拉到極限的：

##### 1. 消除「流水線氣泡（Pipeline Bubbles）」與等待鏈

普通程式（如網頁、辦公軟體）在執行時，經常因為等待硬碟資料、等待網路封包，或因為分支預測失敗（Branch Misprediction）而導致 CPU 的核心流水線出現空轉（稱為氣泡）。

- **測試軟體的做法**：程式碼經過極度精簡與循環展開（Loop Unrolling），沒有任何阻礙執行的判斷式。它確保 CPU 內部的所有算術邏輯單元（ALU）在每一個時脈週期（Clock Cycle）中，都是 **100% 滿載運作**，硬體完全沒有喘息和降溫的時間。

##### 2. 強制喚醒高功耗專用硬體（AVX-512 与 Tensor Core）

這是晶片瓦數瞬間飆破 TDP（熱設計功耗）上限的核心原因。

- **CPU 端（AVX-512 / AMX）**：普通指令一次只能處理 32 位元或 64 位元的純量加法。當軟體調用 AVX-512 指令集時，CPU 內部佔用巨大晶圓面積的**512位元向量執行單元**被全面通電喚醒。這些單元一開動，數萬個電晶體同時高速翻轉，產生的熱量極大，甚至會逼得 CPU 必須觸發硬體保護機制進行「AVX 降頻」。
- **GPU 端（Tensor Core / Matrix Core）**：普通的 3D 渲染只用到 CUDA 核心（或流處理器）。而深度學習測試軟體會直接壓榨專門用於矩陣乘法的 Tensor Core。它在一個時脈週期內進行數百次乘加運算（MAC），讓晶片密集的運算陣列全數超載，瓦數瞬間達到 400W~700W 的極限。

##### 3. 快取記憶體（Cache）死循環壓榨

- 如果 CPU 每次運算都要去慢速的系統記憶體（DRAM）拿資料，CPU 就必須停下來等待（此時功耗會下降）。
- 測試軟體會故意將測試的資料量（Data Set）控制在剛好能完全塞進 CPU 內部 **L1 / L2 / L3 快取記憶體** 的大小。這讓 CPU 能以幾十 GHz 的內部總線頻率，不間斷地在快取與核心之間搬移資料，讓晶片核心內部的物理溫度積聚不散。

# 二、 記憶體（DRAM）與 FIO（儲存）：它們在讀寫什麼？

對硬體而言，**資料的內容（是貓的圖片還是亂數）完全不重要，硬體只在乎「物理行為」與「通道壓力」。**

##### 1. 內存測試（如 MLC, Memtester, Stress-ng）**

- **丟什麼資料？**：軟體會寫入特定的**位元圖樣（Bit Patterns）**，例如 `0x5555`（二進位為 `01010101...`）與 `0xAAAA`（二進位為 `10101010...`），或者隨機亂數（Random Patterns）。
- **底層物理行為**：DRAM 的儲存單元本質上是微小的電容（有電代表 `1`，沒電代表 `0`）。測試軟體寫入 `0x5555` 後立馬切換寫入 `0xAAAA`，是在強迫記憶體顆粒中相鄰的電容**在極短時間內進行完全相反的充放電**。這會產生最大的物理電磁干擾（Cross-talk）與熱量。這種測試是為了誘發位元翻轉錯誤（Bit Flip），藉此考驗伺服器 **ECC（糾錯記憶體）** 的硬體容錯能力與記憶體控制器的穩定性。

##### 2. FIO（儲存吞吐量與 IOPS 測試）

- **丟什麼資料？**：預設通常是**偽隨機數（Pseudo-random data）**。絕對不能用全零（All-zeros）資料，因為現代 SSD 的主控晶片非常聰明，遇到全零資料會啟動內部「硬體壓縮演算法」，直接用標記代替寫入，這樣就測不到真實的硬體壓力。
- **底層物理行為**：當設定 `--direct=1` 時，軟體會繞過作業系統的快取，利用**系統調用（System Call）** 直接將記憶體中的資料物理地址（Physical Address）填入 NVMe 控制器的暫存器。NVMe 控制器隨即啟動 **DMA（直接記憶體存取）**，繞過 CPU，直接從 DRAM 把資料抽乾並砸向 PCIe 匯流排。這會迫使 SSD 主控晶片同時開啟所有快閃記憶體通道（NAND Channels）進行高電壓寫入（擦除與編程），壓榨 PCIe 總線的最高頻寬。

# 三、 網路卡（LAN）與 DPU（如 BlueField-3）：網路通道的壓榨

網路設備的測試（如 iperf3, pktgen, DPDK 測試），其本質是 **「協議棧極限」與「專用硬體加速引擎」的壓榨** 。
##### 1. 傳統網路卡（LAN / NIC）測試

- **底層物理行為**：軟體（如 `pktgen`）在系統記憶體中預先建立一堆空的 TCP/IP 或 UDP 封包，然後以「線速（Line Rate）」將這些封包的記憶體指標丟給網卡驅動。網卡晶片（ASIC）接手後，負責在硬體層計算校驗和（Checksum）、執行分片（TSO），然後透過物理層晶片（PHY）將數據轉換成高速的**電脈衝或光信號**發射出去。
- **對系統的衝擊**：在此過程中，CPU 的瓦數也會上升，因為每秒有數百萬個封包進出，會產生排山倒海的**硬體中斷訊號（Hardware Interrupts）**，強迫 CPU 頻繁切換上下文（Context Switch）來處理網路中斷。

##### 2. DPU / BlueField-3 測試

BlueField-3 這類的 DPU 已經不是單純的網卡，它本身就是一台內嵌在伺服器裡的「微型伺服器」，擁有十幾個 ARM 核心、專用的硬體加速單元與獨立的 PCIe 交換機。

- **底層物理行為**：當測試軟體在跑 DPU 負載時（例如測試 RDMA/RoCE 吞吐量、IPsec 加密、或 OVS 虛擬交換機卸載），軟體是在向 DPU 的暫存器下達專用硬體指令。
- **硬體壓榨點**：資料流進 DPU 後，不會經過傳統 CPU，而是直接進入 DPU 內部的 **Crypto（加密引擎）** 或 **TCAM（三態內容定址記憶體，用於路由查表）**。這些專用晶片電路在進行高速 AES 變換或硬體查表時，同樣會因為電訊號的高頻翻轉而產生巨大熱量與功耗，壓榨的是 DPU 晶片自身的散熱極限。

# 四、 總結：從架構全景看熱負載測試

如果將伺服器硬體架構圖攤開，測試軟體對整個硬體系統實施的只有三件事：

1. **阻斷等待（Keep it Busy）**：用 Direct I/O、記憶體對齊、快取鎖定，切斷所有硬體等待鏈，讓晶片「永遠有下一個指令要執行」。
2. **極端物理干擾（Signal Stress）**：利用特製的資料圖樣（如隨機數、交替位元、矩陣乘法），讓內部半導體、電容、傳輸線路產生最大的物理干擾與電壓波動。
3. **頻寬飽和（Bus Saturation）**：將 PCIe 匯流排、記憶體通道（Memory Channels）、網路光纖的傳輸容量卡在 99% 的飽和邊緣，藉此測試伺服器在最大電流與最高溫度下的**訊號完整性（Signal Integrity）** 與 **供電/散熱模組（Power/Thermal）** 的承載極限。
